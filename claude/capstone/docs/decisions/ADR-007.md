# ADR-007 — Isolar HAL atrás de GpioPort

- Status: aceito
- REQ: REQ-001, REQ-002

## Contexto

A HAL gerada pelo CubeMX muda entre revisões de firmware e não pode ser incluída nos testes que rodam no host. Sem uma abstração, a lógica de `blink` fica impossível de testar sem a placa.

## Decisão

Toda lógica em `app/` recebe uma interface `GpioPort` injetada. A HAL real só aparece em `platform/stm32f1/`.

## Alternativas

1. Chamar `HAL_GPIO_WritePin()` diretamente em `app/blink.c` — rejeitado: impossível testar no host e acopla a família do MCU.
2. Copiar a HAL para `test/` — rejeitado: divergência silenciosa entre o mock e o código real.

## Consequências

+ Testes determinísticos no host com CMock.
+ Um adaptador por família de MCU.
- Mais uma indireção no caminho crítico de GPIO (desprezível para um LED).

## Compliance

- Verificação: `test/test_blink.c` usa `mock_gpio_port.h`; CI falha se `app/` incluir `stm32f1xx_hal.h`.
- Onde roda: jobs `unit:ceedling` e `static:checks`.
- Evidência: `build/artifacts/test/*.xml` e log do job `static:checks`.
- Evidência de hardware: `reports/hil/results.xml` (REQ-001).
