- Flash: st-flash --reset write build/firmware.bin 0x8000000

- Sem malloc/printf; use osal_log()

Regra dura em ação

// .claude/settings.json
"permissions": { "deny": ["Edit(Drivers/**)", "Write(Drivers/**)"] },
"hooks": {
  "Stop": [{ "hooks": [{ "command":
    "ceedling test:all >/dev/null 2>&1 || { echo 'teste vermelho' >&2; exit 2; }"
  }]}]
}
  • Exit 2 devolve o erro e não deixa o turno terminar.
  • onFailure: "block" impede passagem se o scanner cair.
  • Use command/http/mcp_tool: prompt/agent não são determinísticos.

TDD em C no host

1. skill embedded-unit-tests escreve test/test_blink.c
2. ceedling test:test_blink  → VERMELHO
   undefined reference to blink_enter_error
3. implemente o mínimo em app/blink.c
4. ceedling test:all         → VERDE
5. Stop hook garante que ninguém diga "pronto" antes disso

Regra: teste nunca inclui stm32f1xx_hal.h. Use mock_*.h do CMock.

Casos de borda que o modelo esquece

  • Timer 32-bit @1kHz: rollover em 49,7 dias.
  • Buffer circular: cheio e vazio com head == tail.
  • ISR: variável sem volatile, reentrância.
  • DMA: underrun travando o dado.
  • I2C: NACK, clock stretching, bus busy.
  • Reset: watchdog, brownout, estado inicial inválido.

Guarde em references/edge-cases.md da skill.

GitLab CI: separe quem compila de quem toca a placa

stages: [build, unit, static, flash, hil, release]

build:fw      tags: [docker]        → .elf/.bin/.map
unit:ceedling tags: [docker]        → junit + cobertura
flash:bench   tags: [stm32-bench]   → manual, st-flash
hil:gpio      tags: [stm32-bench]   → manual/label, pytest
release:tag   rules: tag v*         → glab release create

flock /tmp/stm32-bench.lock -c "pytest -q tests/hil ..."

HIL: quatro camadas do harness

HOST    → compila, decide o próximo passo
TARGET  → STM32 + ST-Link
BENCH   → Raspberry Pi/Nanopi, fontes, lógico, UART
FIELD   → telemetria do equipamento instalado
  • Um job por placa por vez (flock).
  • Reset para estado conhecido antes de medir.
  • artifacts: when: always — log existe na falha.
  • Fault injection: cortar rail, NACK, watchdog, underrun.

Requirements do GitLab estão migrando para work items. Spec versionada + Issues + MRs + evidência é o caminho estável.

Release com evidência

  • Tag vMAJOR.MINOR.PATCH+kREV — k é a revisão da placa.
  • Changelog gerado de MRs, nunca escrito à mão.
  • Pipeline URL + junit do HIL + cobertura anexados.
  • /verify → /code-review → gates → checklist de 5 itens.
glab release create v1.4.2+k7 build/firmware.bin \
  --notes "$(./scripts/changelog.sh)"
